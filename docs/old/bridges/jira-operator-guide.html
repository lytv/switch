Full guideline: Jira triggers a Switch agent

Jira does not open a chat. Jira sends an event. Switch posts one addressed message in a Mattermost room. The named agent then wakes and works.

Local machine guide. Verified 10 Sep 2026. Secrets stay in .env and the dashboard Setup panel. Do not put tokens in this file or in a rule field.

1. The idea

Jira story moves→ Webhook POST→ Switch matches a rule→ Room message @agent→ Agent starts

The poster is the system agent jira. The worker is the agent you name on the rule, for example opencode.

2. Three places (do not mix them)

3. How to sign in

Dashboard

  • Email: admin@switch.local
  • Password: field GATEWAY_ADMIN_PASSWORD in the repo-root .env

Mattermost

  • Team: switch
  • Admin user: admin - password MATTERMOST_ADMIN_PASSWORD in the same .env
  • Normal user: user — password MATTERMOST_USER_PASSWORD

The long dashboard password is not the Mattermost password.

4. Daily use

  1. Keep these running: Postgres/Mattermost (just up), Switch core (just run), dashboard (just gateway-dev), ngrok to port 8000.
  2. Open Mattermost room jira.
  3. In Jira project KAN, move a Story to Done.
  4. Switch posts: KAN-123 summary is now Done, addressed to opencode.
  5. If you need to change who wakes, or which status fires, edit the rule on the dashboard Jira page. Click Test rule before you rely on it.
  6. If nothing appears, open Delivery history on the Jira page. A good fire shows status delivered.

6. Live setup (this machine)

Verified working. A real Jira Cloud transition of KAN-111 returned Switch delivery delivered.

  • Webhook URL shape: https://<public-host>/integrations/jira/local
  • Tunnel target: Switch API localhost:8000 (not 3000, not 5173)
  • Jira Cloud webhook: issue created + updated, JQL filter project = KAN (or your project key)
  • System agent jira exists and is a member of room jira
  • Worker opencode is a member of room jira
  • The tunnel adds header X-Switch-Secret, so the Jira classic webhook does not need a custom header

Copy or rotate the secret only from the dashboard Jira Setup panel. After a rotate, restart Switch core and ngrok so both still match.

7. Add another rule

  1. Dashboard → Jira → New rule.
  2. Set instance to local (same as the webhook path).
  3. Set project key to KAN or leave blank for every project.
  4. Pick fire-on, status, room, and agent.
  5. Invite both jira and the target agent into that room.
  6. Click Test rule. Confirm match and rendered text. Test does not post.
  7. Save. Move a matching Jira story. Check Delivery history, then Mattermost.

Useful fire-on choices

  • transition + status Done — when a story enters Done (your current rule).
  • created — when a new Story is filed.
  • updated + status In Progress — when the current status is In Progress.

11. Security

  • Never commit .env.
  • Never put an API token in a rule field.
  • Rotate any Jira API token that was pasted in chat.
  • The ngrok URL is public. Keep the secret strong. Stop ngrok when you do not need Jira to reach this laptop.
